# T2 spike: WebKitGTK rendering (disposable)

Isolated Vite project used to measure markdown + Mermaid + scroll performance inside the
real Tauri webview. It is **not** part of the app build: the app entry never imports it,
Tailwind skips it (`@source not` in `src/index.css`) and it has its own `vite.config.ts`.
Results and decisions live in `.specs/features/quire-v0-1/summary.md` (Journal, T2).
Delete this folder (and the `spike:*` scripts) once T16 lands.

The document is generated by `generate.ts` (synthetic, ~40 KB per unit of scale).

## Run

From `apps/desktop`:

```bash
pnpm spike:build
SPIKE_REPORT=/tmp/spike.jsonl pnpm tauri dev --config \
  '{"build":{"beforeDevCommand":"pnpm spike:preview","devUrl":"http://localhost:1420/?i=0"}}'
```

Each run POSTs a JSON line to `$SPIKE_REPORT` (or stdout). Keep the window visible while it
runs: WebKit throttles frames in hidden windows.

Query parameters:

| Param | Effect |
| --- | --- |
| `i=0` | automatic plan: 3× scale 1, 2× scale 3, 1× scale 1 (reloads itself) |
| `manual&scale=N` | single run at scale N, then stays open for manual scrolling |
| `layout=dagre` | Mermaid layout (Mermaid 12 defaults to ELK, ~1.5 MB) |
| `engine=oniguruma` | Shiki WASM engine instead of the JS regex engine |
| `nomermaid` / `plain` | skip Mermaid / skip Mermaid and Shiki (memory attribution) |
| `mode=empty` | empty page (memory baseline) |

Memory was sampled outside the webview as the PSS sum of `quire` and its WebKit child
processes (`/proc/<pid>/smaps_rollup`).
